# Living Car

**Living Things / Cloud DNA — Concept by Evgenii Bogomazov-Pusser, Independent Researcher, Israel.**

Исследовательский Python-прототип автомобиля как взаимосвязанного адаптивного технологического тела. Передвижение, защита, комфорт и сохранение функциональности рассматриваются как отдельные цели. Проект проверяет гипотезу; положительный результат не заложен в метрики.

## Открыть по ссылке — без установки

**https://living-car-lab.pusser.chatgpt.site**

Общедоступная веб-версия работает в браузере без Python и команд. Ссылку можно пересылать другим людям; ваш компьютер не должен оставаться включённым. При первом открытии загружается физический движок, затем доступны пять опытов, 3D, сравнение, параметры, воспроизведение и экспорт JSON.

**Локальный файл:** откройте `Living Car.html` в корне проекта или `web/index.html`. Это один автономный HTML со встроенными стилями, 3D-библиотекой, физическим движком и моделями. Его можно открывать кнопкой браузера в PyCharm. Установка и отдельный сервер не требуются. Полный HTML занимает около 15 МБ, поскольку включает MuJoCo WASM; внешний интернет для работы самого файла не требуется.

Исходники веб-версии находятся в `web/`; редактируемый шаблон — `web/template.html`, `web/index.html` — сгенерированный автономный файл. Команда `npm run build` внутри `web/` обновляет автономные копии. Браузер использует официальный MuJoCo 4.0.1 WebAssembly, те же сгенерированные Python-модели и порт ограниченного управления, пластичности и ремонта. Для первого бокового опыта вычисленные сила, ускорение, повреждение и энергия совпали с Python-версией с точностью численного округления.

**GitHub Pages:** готовая страница также лежит в `docs/index.html`. После загрузки репозитория на GitHub можно выбрать Settings → Pages → Deploy from a branch → main → /docs. Для публикации не нужны Node или Python на стороне посетителя.

Сайт опубликован с доступом `public`; регистрация посетителя не требуется. Персональные файлы, профили и SQLite-архивы на сайт не загружаются. Нативная Python-программа ниже остаётся доступна для дальнейшей разработки и исследований.

## Открыть программу

На этом компьютере зависимости уже установлены в `.venv312` (Python 3.12).

**Дважды нажмите `Start Living Car.cmd` в этой папке.**

Или из PowerShell:

```powershell
cd 'C:\Users\evgen\Codes\Living Things\living-car'
.\.venv312\Scripts\python.exe -m living_car gui
```

В окне:

1. Нажмите **Play** под 3D-сценой. Вращение — перетаскиванием мыши; масштаб — колёсиком.
2. Переключайте **Living Car / Conventional**: обе траектории рассчитаны с одинаковыми массой, начальными условиями и зерном.
3. Выберите **X-ray, Exterior, Structure, Sensors, Contact loads, Damage, Stiffness**. Щелчок по компоненту открывает его состояние справа. Поля представлены значениями на механических элементах, а не континуальным FEM-полем.
4. Слева выберите опыт, скорость, поведение и ресурсы, затем нажмите **Run paired experiment**. Изменения входов действуют после нового запуска.
5. **Export experiment · JSON** сохраняет обе траектории и условия; **Open saved replay** воспроизводит их без пересчёта. Профиль владельца из экспорта исключается.

Если первоначальный расчёт ещё идёт, подождите несколько секунд. Timeline показывает **физическое время в секундах**, а не условные годы эксплуатации.

## Что реализовано

- Генеративная параметрическая модель MuJoCo: шасси, защищённая ячейка, пружинные панели оболочки, механические связи между соседями, передние и задние зоны смятия, двигатель на ограниченной направляющей, подвеска и колёса.
- Пять сценариев: боковой контакт, узкий зазор без намеренного контакта, фронтальный и косой низкоскоростные удары, локальное восстановление покрытия.
- Реальные интегрируемые механические связи: изменение одного звена передаёт силы другим; 3D-визуализация воспроизводит вычисленные координаты.
- Ограниченный объяснимый контроллер: сенсоры зазора, ограничение сил, хода, упругой деформации и энергии; пассивный режим при исчерпании бюджета. **Это правила управления, а не обученная нейросеть.**
- Упрощённая пластичность связей и конечные ресурсы ремонта малых дефектов. Пластические повреждения не исчезают при ремонте покрытия.
- Виртуальные владельцы и локальные эргономические цели. Они пока не являются биомеханической моделью и не изменяют расчёт столкновения.
- Генотип действительно задаёт топологию тела, параметры связей, сенсоров, ограничения и управление. Мутации сохраняют родителей и номера поколений.
- Запускаемый из CLI поиск мутаций с отдельными критериями, независимым набором проверок и консервативным Pareto-фильтром.
- Локальный прототип Egregor: популяция делится измеренным опытом, предлагает перенос демпфирования, повторно проверяет совместимость и результаты перед допуском. Непрошедшие изменения не распространяются.
- SQLite-архив, переносимый JSON, сравнительные графики, тесты воспроизводимости и физических ограничений.

## Границы этой версии

Готов **Physical Body MVP** и небольшие проверяемые прототипы ремонта/генотипов/коллективного отбора. Полная программа исследований из задания не объявляется завершённой.

Пока **нет** обученного PyTorch/RL-мозга, FEniCS/FEM, континуальной деформации материалов, расчётной теплопроводности, полномасштабной Lifetime Simulation, реального облака, эволюции технологических видов или валидации по натурным краш-тестам. Жёсткость и демпфирование сейчас задаются генотипом; пространственное перераспределение сил обеспечивают механические связи и управление оболочкой. Это не доказательство преимуществ Living Car для реальных автомобилей.

## Воспроизводимый первый эксперимент

```powershell
.\.venv312\Scripts\python.exe -m living_car experiment
```

Результат в `results/first-experiment/`:

- `RESULTS.md` — сравнение и ограничения;
- `comparison.png` — четыре графика;
- `experiment.json` — условия, генотип, метрики и обе траектории;
- `archive.sqlite` — локальный архив.

При боковом контакте на 1 м/с в модели с зерном 42 адаптивный вариант дал **меньшее остаточное повреждение, но большую пиковую контактную силу и ускорение ячейки**, затратив энергию на управление. Это компромисс, а не безусловное улучшение безопасности. Точные значения — в отчёте.

Другие опыты:

```powershell
.\.venv312\Scripts\python.exe -m living_car experiment --scenario frontal --speed 1.5 --output results/frontal
.\.venv312\Scripts\python.exe -m living_car experiment --scenario near_miss --output results/near-miss
.\.venv312\Scripts\python.exe -m living_car experiment --scenario micro_damage --output results/repair
.\.venv312\Scripts\python.exe -m living_car gui --replay results/first-experiment/experiment.json
```

Конфигурация JSON может быть передана через `experiment --config path.json`; поля описаны в `schema.py`. Seed определяет исходные микродефекты и мутации; при текущих контактных опытах без микродефектов траектория детерминирована и не зависит от seed.

## Cloud DNA и Egregor

```powershell
.\.venv312\Scripts\python.exe -m living_car evolve --candidates 3 --generations 2
.\.venv312\Scripts\python.exe -m living_car collective
```

Обучающий набор поиска: боковой, фронтальный контакт и узкий зазор при 1 м/с; проверочный — те же сценарии при 1.35 м/с. Это **ограниченная проверка на другой скорости**, не исчерпывающая независимая инженерная валидация. В каждом наборе сохраняются худшие значения пяти отдельных критериев: сила, повреждение, ускорение, энергия и вторжение в ячейку. Улучшение допускается, только если ни один критерий не ухудшился и хотя бы один улучшился в обоих наборах.

Если потомки не проходят проверку, поиск останавливается. Надпись Generation 3 не появляется сама собой. Коллективный эксперимент переносит только проверенное демпфирование; он не притворяется облачным интеллектом.

## Установка на другом компьютере

Рекомендуется Python **3.12**. Основной пакет поддерживает Python 3.11+, но доступность binary wheels визуализации зависит от версии Python и ОС.

```powershell
py -3.12 -m venv .venv312
.\.venv312\Scripts\python.exe -m pip install -e '.[desktop,test]'
.\.venv312\Scripts\python.exe -m living_car gui
```

Для расчётов без GUI достаточно `pip install -e '.[test]'`. Проверенный снимок установленных библиотек находится в `requirements-tested.txt`. Дополнительный набор `learning` зарезервирован для последующей реализации Gymnasium/PyTorch; эта версия его не требует и не заявляет обучение.

## Проверки

```powershell
.\.venv312\Scripts\python.exe -m pytest -q
.\.venv312\Scripts\python.exe -m living_car gui --smoke
```

Проверяются сохранение энергии/скорости в свободном пассивном движении, равенство масс и условий, реальные контактные силы, сходимость интегрирования при уменьшении шага, взаимосвязь соседних панелей, ограничения управления/ремонта, воспроизводимость полных траекторий, генеративность генотипа, родословная, отбор, приватность и воспроизведение экспорта. GUI-smoke переключает виды и архитектуры, перемещает timeline, запускает воспроизведение и сохраняет снимки в `results/`.

## Структура

```text
src/living_car/
  schema.py       Входы, генотип, владельцы и ограничения
  body.py         Генерация реального multibody-тела MuJoCo
  brain.py        Ограниченный объяснимый контроллер
  simulation.py   Интегрирование, контакт, пластичность, ремонт, метрики
  evolution.py    Мутации, независимые проверки, коллективный перенос
  archive.py      SQLite, происхождение генотипов и результаты
  io.py           JSON и проверка воспроизводимых траекторий
  desktop.py      Нативный Qt/PyVista интерфейс
  report.py       Графики и результаты
  cli.py          Команды запуска
docs/MODEL.md     Уравнения, допущения и ограничения
tests/            Автоматические проверки
```

Персональные настройки хранятся только в `data/local-profile.json`; архив в `data/experiments.sqlite`. Ничего не отправляется по сети во время работы симулятора.
